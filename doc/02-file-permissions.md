# 02. 파일 권한

> 보고서 대응: [6번 권한 실습](../README.md), 14-4 권한 숫자 표기 규칙

---

## 1. 왜 권한이 필요한가

유닉스 계열 OS는 여러 사용자가 한 컴퓨터를 쓰는 것을 전제로 설계됐다. 그래서 모든 파일에 **"누가 무엇을 할 수 있는가"** 가 붙어 있다.

혼자 쓰는 노트북에서도 이 개념은 살아 있다. 실제로 SSH 개인키는 권한이 잘못되면 SSH가 **사용 자체를 거부한다**(뒤에서 다룬다). 권한을 모르면 원인을 찾을 수 없다.

---

## 2. `ls -l` 출력 해부

보고서 6번에서 실제로 나온 출력이다.

```
-rw-r--r--@ 1 kim  staff  20 Aug  5 19:23 note.txt
```

이걸 쪼개면 이렇게 된다.

```
-  rw-  r--  r--  @   1   kim   staff   20   Aug 5 19:23   note.txt
│   │    │    │   │   │    │      │      │        │           │
│   │    │    │   │   │    │      │      │        │           └─ 이름
│   │    │    │   │   │    │      │      │        └─ 수정 시각
│   │    │    │   │   │    │      │      └─ 크기(바이트)
│   │    │    │   │   │    │      └─ 그룹
│   │    │    │   │   │    └─ 소유자
│   │    │    │   │   └─ 하드링크 수
│   │    │    │   └─ 확장 속성 있음 (macOS 전용 표시)
│   │    │    └─ 기타(others) 권한
│   │    └─ 그룹(group) 권한
│   └─ 소유자(user) 권한
└─ 파일 종류
```

### 첫 글자 — 파일 종류

| 문자 | 의미 |
| :--- | :--- |
| `-` | 일반 파일 |
| `d` | 디렉토리 (directory) |
| `l` | 심볼릭 링크 |

```
-rw-r--r--   note.txt      ← 일반 파일
drwxr-xr-x   workspace     ← 디렉토리
```

### 다음 9글자 — 권한 3세트

```
rw- r-- r--
└┬┘ └┬┘ └┬┘
 │   │   └─ others: 나머지 모든 사용자
 │   └───── group:  파일이 속한 그룹의 구성원
 └───────── user:   소유자
```

각 세트는 항상 `rwx` 순서이며, 없으면 `-` 로 표시된다.

## 3. r, w, x 의 의미

**파일과 디렉토리에서 의미가 다르다.** 여기가 가장 헷갈리는 부분이다.

| 권한 | 파일에서 | 디렉토리에서 |
| :--- | :--- | :--- |
| `r` (read) | 내용을 읽을 수 있다 | 안의 **목록**을 볼 수 있다 (`ls`) |
| `w` (write) | 내용을 수정할 수 있다 | 안에 파일을 **만들거나 지울** 수 있다 |
| `x` (execute) | 프로그램으로 **실행**할 수 있다 | 안으로 **진입**할 수 있다 (`cd`) |

### 디렉토리의 `x` 가 핵심

디렉토리에서 `x` 는 "실행"이 아니라 **통과(traverse) 권한**이다. 이게 없으면 안으로 들어갈 수 없고, 안의 파일에 접근할 수도 없다.

```bash
mkdir test && echo "secret" > test/a.txt

chmod 600 test          # rw-  →  r는 있고 x는 없음
ls test                 # 목록은 보인다
# a.txt
cat test/a.txt          # 하지만 접근은 안 된다
# cat: test/a.txt: Permission denied

chmod 700 test          # x 추가
cat test/a.txt
# secret
```

**그래서 디렉토리 권한은 거의 항상 `x` 를 포함한다.** `755`, `700` 처럼. `644` 짜리 디렉토리는 목록만 보이고 쓸모가 없다.

### `w` 의 함정

파일을 지울 수 있는지는 **파일의 권한이 아니라 그 파일이 든 디렉토리의 권한**이 결정한다.

```bash
mkdir box && echo "x" > box/readonly.txt
chmod 444 box/readonly.txt     # 파일은 읽기 전용

rm box/readonly.txt            # 그래도 지워진다 (디렉토리에 w가 있으므로)
```

파일 삭제는 "디렉토리에서 이름을 제거하는 작업"이기 때문이다. 파일 자체를 건드리는 게 아니다.

## 4. 숫자 표기 규칙

### 1단계 — 각 권한에 값 부여

| 권한 | 값 | 이진수 |
| :--- | :--- | :--- |
| `r` | 4 | 100 |
| `w` | 2 | 010 |
| `x` | 1 | 001 |

값이 4, 2, 1인 이유는 **2진수 세 자리**이기 때문이다. 각 자리가 독립적인 on/off 스위치라서 합쳐도 원래 조합을 알 수 있다.

```
rwx = 111(2진수) = 4+2+1 = 7
rw- = 110(2진수) = 4+2+0 = 6
r-x = 101(2진수) = 4+0+1 = 5
r-- = 100(2진수) = 4+0+0 = 4
```

### 2단계 — 세 자리로 조합

**소유자 → 그룹 → 기타** 순서로 붙인다.

```
   7        5        5
   │        │        │
  rwx      r-x      r-x
 4+2+1    4+0+1    4+0+1
소유자    그룹     기타
```

### 자주 쓰는 조합

| 숫자 | 문자 | 용도 |
| :--- | :--- | :--- |
| `644` | `rw-r--r--` | 일반 파일 기본값. 소유자만 수정, 나머지는 읽기만 |
| `755` | `rwxr-xr-x` | 디렉토리·실행파일 기본값 |
| `600` | `rw-------` | 비밀 파일. 소유자만 접근 (SSH 개인키, `.env`) |
| `700` | `rwx------` | 비밀 디렉토리 (`~/.ssh`) |
| `777` | `rwxrwxrwx` | **누구나 모든 것 가능 — 쓰지 말 것** |

> `777` 은 "권한 문제가 나면 일단 777" 이라는 잘못된 습관에서 나온다. 보안 사고의 흔한 원인이므로, 무엇이 부족한지 정확히 파악해서 최소 권한만 주는 습관을 들인다.

## 5. chmod — 권한 바꾸기

### 숫자 방식 (절대 지정)

```bash
chmod 600 note.txt         # rw-------
chmod 700 workspace        # rwx------
chmod 755 script.sh        # rwxr-xr-x
```

현재 권한과 무관하게 **덮어쓴다**.

### 기호 방식 (상대 변경)

```bash
chmod u+x script.sh        # 소유자에게 실행 권한 추가
chmod go-w file.txt        # 그룹·기타에서 쓰기 권한 제거
chmod a+r file.txt         # 모두에게 읽기 추가
chmod u=rw,go= secret.txt  # 소유자는 rw, 나머지는 아무것도 (= 600)
```

| 대상 | 의미 |
| :--- | :--- |
| `u` | user (소유자) |
| `g` | group |
| `o` | others |
| `a` | all (= ugo) |

| 연산 | 의미 |
| :--- | :--- |
| `+` | 추가 |
| `-` | 제거 |
| `=` | 정확히 이것만 |

**어느 쪽을 쓰나?** 최종 상태를 확실히 하려면 숫자, 기존 권한을 유지하며 하나만 바꾸려면 기호를 쓴다.

### 재귀 적용

```bash
chmod -R 755 mydir         # 하위 전체에 적용
```

> 파일과 디렉토리에 같은 값을 주므로 주의. 파일에 `x` 가 붙는 게 싫으면 이렇게 나눈다:
> ```bash
> find mydir -type d -exec chmod 755 {} \;   # 디렉토리는 755
> find mydir -type f -exec chmod 644 {} \;   # 파일은 644
> ```

## 6. 실전 사례 — SSH 키

권한이 실제로 강제되는 대표 사례다. 보고서 17-5에서 확인한 내용이다.

```bash
stat -f "%Sp %OLp %N" ~/.ssh/id_ed25519 ~/.ssh/id_ed25519.pub
# -rw------- 600 /Users/kim/.ssh/id_ed25519
# -rw-r--r-- 644 /Users/kim/.ssh/id_ed25519.pub
```

| 파일 | 권한 | 이유 |
| :--- | :--- | :--- |
| 개인키 `id_ed25519` | `600` | 나만 알아야 하는 값. 남이 읽으면 신원 도용 |
| 공개키 `id_ed25519.pub` | `644` | 어차피 남에게 주는 값. 열려 있어도 무방 |

**개인키 권한이 열려 있으면 SSH가 거부한다.**

```bash
chmod 644 ~/.ssh/id_ed25519      # 일부러 열어보면
ssh -T git@github.com
# @@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
# @    WARNING: UNPROTECTED PRIVATE KEY FILE!          @
# @@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
# Permissions 0644 for '/Users/kim/.ssh/id_ed25519' are too open.
# This private key will be ignored.

chmod 600 ~/.ssh/id_ed25519      # 되돌린다
```

SSH가 이렇게까지 하는 이유는, 개인키 유출이 곧 신원 탈취이기 때문이다. 권한 숫자가 추상적인 규칙이 아니라 실제 보안 도구에서 강제되는 것을 보여주는 사례다.

## 7. umask — 기본 권한이 정해지는 방식

새 파일을 만들면 왜 `644` 이고 디렉토리는 `755` 일까? **umask** 가 결정한다.

```bash
umask
# 022
```

umask는 "빼는 값"이다.

```
파일:      기본 666 - umask 022 = 644  (rw-r--r--)
디렉토리:  기본 777 - umask 022 = 755  (rwxr-xr-x)
```

파일의 기본값이 `777`이 아니라 `666`인 이유는, **새 파일에 실행 권한을 자동으로 주면 위험하기 때문**이다. 실행이 필요한 파일은 사람이 직접 `chmod +x` 를 해야 한다.

## 8. 직접 해보기

```bash
cd ~/Desktop
mkdir perm-practice && cd perm-practice

# 파일과 디렉토리 준비
echo "test" > note.txt
mkdir workspace

# 변경 전 확인
ls -l note.txt         # -rw-r--r--  (644)
ls -ld workspace       # drwxr-xr-x  (755)

# 권한 변경
chmod 600 note.txt
chmod 700 workspace

# 변경 후 확인
ls -l note.txt         # -rw-------  (600)
ls -ld workspace       # drwx------  (700)

# 숫자와 문자 동시 확인 (macOS)
stat -f "%Sp %OLp %N" note.txt workspace

# 디렉토리 x 권한 실험
echo "secret" > workspace/a.txt
chmod 600 workspace          # x 제거
ls workspace                 # 목록은 보임
cat workspace/a.txt          # Permission denied
chmod 700 workspace          # x 복구
cat workspace/a.txt          # secret

# 정리
cd ~/Desktop && rm -r perm-practice
```

**확인 문제**

1. `chmod 640 file.txt` 는 문자로 어떻게 표시되나?
2. 디렉토리에 `r` 은 있고 `x` 가 없으면 무엇이 되고 무엇이 안 되나?
3. `755` 를 계산 과정과 함께 설명해 보라.

<details>
<summary>답</summary>

1. `-rw-r-----` — 소유자 `rw`(6), 그룹 `r`(4), 기타 없음(0)
2. `ls` 로 이름 목록은 볼 수 있지만, `cd` 로 진입하거나 안의 파일을 읽을 수 없다
3. 소유자 `rwx`=4+2+1=7, 그룹 `r-x`=4+0+1=5, 기타 `r-x`=4+0+1=5 → `755`
</details>

## 9. 자주 하는 실수

| 실수 | 결과 | 해결 |
| :--- | :--- | :--- |
| 권한 문제에 `777` 남발 | 보안 구멍 | 정확히 무엇이 부족한지 확인 후 최소 권한만 |
| 디렉토리에서 `x` 제거 | 진입·접근 불가 | 디렉토리는 `x` 유지 (`755`/`700`) |
| `ls -l dir` 로 디렉토리 권한 확인 | 안의 파일 권한이 나옴 | `ls -ld dir` |
| `chmod -R 755` 를 소스 폴더에 | 모든 파일에 실행 권한 | `find` 로 타입별 분리 적용 |
| SSH 키 권한 방치 | SSH가 키를 무시 | 개인키는 `600` |

### A. 루브릭 직결 문항

#### A-1. 파일 권한 숫자 표기(예: 755, 644)가 어떤 규칙으로 결정되는지 설명할 수 있는가?

**⚡ 답변 — 2단계로 나눠 말한다**

> **1단계, 각 권한에 값이 정해져 있습니다.** 읽기 `r` 은 4, 쓰기 `w` 는 2, 실행 `x` 는 1입니다.
>
> **2단계, 대상별로 합산해 세 자리를 만듭니다.** 순서는 **소유자 → 그룹 → 기타**입니다.

**칠판에 그려도 되는 계산**

```
755  →  rwx    r-x    r-x
        4+2+1  4+0+1  4+0+1
          7      5      5
        소유자   그룹    기타
```

**실습에서 쓴 값으로 이어 말한다**

| 숫자 | 문자 | 계산 | 의미 |
| :--- | :--- | :--- | :--- |
| 644 | `rw-r--r--` | 4+2 / 4 / 4 | 일반 파일 기본값 |
| 600 | `rw-------` | 4+2 / 0 / 0 | 소유자만 (실습의 `note.txt`) |
| 755 | `rwxr-xr-x` | 4+2+1 / 4+1 / 4+1 | 디렉토리·실행파일 기본값 |
| 700 | `rwx------` | 4+2+1 / 0 / 0 | 소유자만 (실습의 `workspace`) |

**"왜 하필 4, 2, 1인가?"를 물으면 — 이걸 답하면 이해도가 드러난다**

> 2의 거듭제곱이라 **합쳐도 원래 조합을 되돌릴 수 있기** 때문입니다. 3비트 이진수로 보면 `rwx` 가 각각 한 자리를 차지합니다.
>
> ```
> r w x
> 4 2 1
> 1 0 1  →  5  →  r-x
> 1 1 1  →  7  →  rwx
> 1 1 0  →  6  →  rw-
> ```
>
> 만약 값이 3, 2, 1이었다면 3은 `r` 인지 `w+x` 인지 구분할 수 없습니다.

**📄 근거**: 보고서 **14-4** (계산 표) + **6번** (`ls -l` 전후 실측)

---

#### B-2. 디렉토리의 실행 권한(`x`)은 무슨 의미인가?

> **실행이 아니라 진입(traverse) 권한**입니다. 없으면 `cd` 로 들어갈 수 없고, 안의 파일 경로를 알아도 접근할 수 없습니다.

동작 차이를 표로 보면 이렇다.

| 디렉토리 권한 | `ls` 로 이름 목록 | `cd` 진입 | 안의 파일 읽기 |
| :--- | :--- | :--- | :--- |
| `r--` (4) | ✅ | ❌ | ❌ |
| `--x` (1) | ❌ | ✅ | ✅ (경로를 정확히 알면) |
| `r-x` (5) | ✅ | ✅ | ✅ |

> 그래서 디렉토리는 보통 `755` 나 `700` 처럼 `x` 를 포함해 줍니다. `644` 를 주면 목록은 보이는데 들어갈 수가 없습니다.

---

#### B-3. 파일 삭제 권한은 어디서 결정되나?

> 파일 자체가 아니라 **그 파일이 든 디렉토리의 `w` 권한**입니다. 삭제는 파일 내용을 건드리는 게 아니라 **디렉토리에서 이름을 제거하는 작업**이기 때문입니다.
>
> 그래서 읽기 전용(`444`) 파일이라도 부모 디렉토리에 쓰기 권한이 있으면 지워집니다. 반대로 파일이 `777` 이어도 부모 디렉토리에 `w` 가 없으면 못 지웁니다.

직관에 어긋나는 부분이라 자주 나오는 질문이다.

---

#### B-4. `chmod 777` 은 왜 나쁜가?

> 모든 사용자가 읽고 쓰고 실행할 수 있게 됩니다. "권한 문제"를 빠르게 없애려고 쓰는 경우가 많은데, 거의 항상 잘못된 선택입니다.
>
> 웹 서버 디렉토리가 `777` 이면 아무나 파일을 심을 수 있고, 그게 실행 가능한 스크립트라면 서버가 통째로 넘어갑니다. **필요한 최소 권한만 주는 것**이 원칙이고, 문제가 생기면 누구에게 무슨 권한이 필요한지부터 따져야 합니다.

---

#### B-5. 숫자 표기와 기호 표기 중 언제 무엇을 쓰나?

```bash
chmod 644 file.txt      # 숫자 — 최종 상태를 확정
chmod u+x script.sh     # 기호 — 기존 권한을 유지하며 일부만 변경
chmod go-w file.txt     # 그룹·기타의 쓰기만 제거
chmod a+r file.txt      # 전체에 읽기 추가
```

| | 숫자 | 기호 |
| :--- | :--- | :--- |
| 방식 | 9비트를 통째로 덮어씀 | 기존 값에서 더하거나 뺌 |
| 적합 | 최종 상태가 명확할 때 | 한 가지만 바꾸고 싶을 때 |

> 기호 표기의 대상은 `u`(소유자) `g`(그룹) `o`(기타) `a`(전체)이고, 연산자는 `+` `-` `=` 입니다.

---

#### B-6. 새로 만든 파일이 644, 디렉토리가 755인 이유는?

> **umask** 때문입니다. 시스템 기본값이 파일 `666`, 디렉토리 `777` 인데 여기서 umask 값을 빼서 결정됩니다. 보통 umask가 `022` 라 파일은 `666-022=644`, 디렉토리는 `777-022=755` 가 됩니다.
>
> 파일 기본값에 `x` 가 없는 이유는, 새로 만든 파일이 자동으로 실행 가능하면 위험하기 때문입니다.

```bash
umask          # 현재 값 확인
```

---

#### B-7. 소유자가 아닌데 권한을 바꾸려면?

> `chmod` 는 **파일 소유자와 root만** 실행할 수 있습니다. 남의 파일 권한은 `sudo` 없이는 못 바꿉니다. 소유자 자체를 바꾸는 `chown` 은 root 전용입니다.

---

### C. 실전 시나리오

#### C-1. "스크립트를 실행하려니 `Permission denied` 가 납니다."

> 대부분 실행 권한이 없는 경우입니다.
>
> ```bash
> ls -l script.sh          # x 가 있는지 확인
> chmod +x script.sh       # 실행 권한 부여
> ```
>
> 그래도 안 되면 **스크립트가 든 디렉토리에 `x` 가 있는지** 봅니다. 진입 권한이 없으면 파일에 도달할 수 없습니다.

---

#### C-2. SSH 키를 만들었는데 접속이 안 됩니다.

> 개인키 권한을 봅니다. **`600` 이 아니면 SSH가 사용을 아예 거부**합니다.
>
> ```
> @@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
> @    WARNING: UNPROTECTED PRIVATE KEY FILE!             @
> @@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
> Permissions 0644 for '.../id_ed25519' are too open.
> This private key will be ignored.
> ```
>
> ```bash
> chmod 600 ~/.ssh/id_ed25519
> chmod 700 ~/.ssh
> ```
>
> **이 규칙이 실제로 강제되는 대표 사례**입니다. 보고서 17-5에 `ls -l` 실측 출력이 있는데 개인키는 `-rw-------`(600), 공개키는 `-rw-r--r--`(644)로 갈립니다. 공개키는 어차피 배포하는 값이라 열어둬도 되고, 개인키는 남이 읽으면 계정을 탈취당하기 때문입니다.

이 사례를 곁들이면 "숫자를 외웠다"가 아니라 "왜 그렇게 주는지 안다"로 들린다.

---

#### C-3. 권한을 바꿨는데도 접근이 안 됩니다.

> 파일 하나만 보지 말고 **경로 전체**를 봅니다. `/a/b/c/file.txt` 에 접근하려면 `a`, `b`, `c` 모두에 `x`(진입) 권한이 있어야 합니다. 중간 디렉토리 하나가 막혀 있으면 최종 파일 권한과 무관하게 실패합니다.
>
> ```bash
> ls -ld / /a /a/b /a/b/c        # 경로를 단계별로 확인
> ```
